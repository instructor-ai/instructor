# Usage accounting audit

Audit base: **`24752a62`**, refreshed from `origin/main`. Documentation accessed **2026-09-09 UTC**. This is an audit of Instructor 1.17.0's implemented paths, not a claim of live-provider or invoice parity. No inference requests, credentials, account usage queries, or paid API calls were used.

Instructor currently has two typed retry accumulators: OpenAI **Chat Completions** and Anthropic **stable Messages**. They mutate response usage into cumulative usage. OpenAI Responses, Anthropic beta Messages, and most native SDK integrations do not enter those accumulators. The same wire response can therefore have different observable accounting depending on the SDK used to decode it.

This PR adds evidence, documentation, and a targeted backward-compatible fix for Anthropic thinking-token dictionary details; it introduces no new runtime abstraction. Existing callers and tests depend on cumulative `completion.usage`; removing that mutation needs a migration decision.

## Evidence and scope

- **Code**: implementation at the base revision; source links below are revision-bound.
- **SDK**: local installed model definitions, inheritance, defaults, and serialization; exact versions and 26 type inventories are in [sdk-inventory.json](sdk-inventory.json). These are examined versions, not latest-version claims. The environment includes optional SDKs; it is not a fresh lockfile install.
- **Contract**: [offline SDK-object tests](https://github.com/567-labs/instructor/blob/codex/usage-accounting-audit/tests/test_usage_accounting_audit.py). Tests named `current` reproduce a limitation and should change with its fix; they are not a promise to retain that behavior. No mocks or transport substitutes.
- **Docs**: official provider documentation, linked beside each claim. Rolling docs may describe fields newer than the examined SDK. A documented field absent from an SDK is explicitly distinguished below.
- **Inference / unresolved**: identified explicitly. No measured server billing, cancellation, or stream-finalization evidence exists in this audit.

Provider discovery uses [Provider enum](https://github.com/567-labs/instructor/blob/24752a62/instructor/v2/core/providers.py#L11), [23 provider specifications](https://github.com/567-labs/instructor/blob/24752a62/instructor/v2/core/provider_specs.py#L115), factory implementations, and mode registration. `GOOGLE` and `UNKNOWN` enum values are not independent service integrations; `google` is a GenAI alias. The generic `from_openai` and `from_litellm` escape hatches permit arbitrary endpoints/backends, so no finite list establishes their accounting semantics. New providers only proposed in PRs are not counted as current integrations. There is no `instructor/v3` runtime directory at this base.

## Findings ranked by impact

### 1. High: cumulative responses erase attempt boundaries and can be counted twice

[usage.py:41](https://github.com/567-labs/instructor/blob/24752a62/instructor/v2/core/usage.py#L41) modifies the **original SDK usage instance**, including nested details. [retry.py:326](https://github.com/567-labs/instructor/blob/24752a62/instructor/v2/core/retry.py#L326) calls the response hook first, then mutates that same response, then emits a copied cumulative usage snapshot. Async does the same at [retry.py:622](https://github.com/567-labs/instructor/blob/24752a62/instructor/v2/core/retry.py#L622).

Contract reproduction: attempt totals 15 and 27 produce returned response totals **15 and 42**. Summing retained response-hook objects or failed-attempt completions yields **57**, although the observed calls consumed **42**. The final `_raw_response.usage` and `create_with_completion` usage represent accumulated attempts, not the final provider response alone. A synchronous hook that immediately serializes usage sees attempt data; a hook retaining the response reference sees its later mutated form. This is a compatibility hazard for logging and invoice reconciliation, not evidence that Instructor itself adds 57 internally.

Safe next step: document this behavior and demonstrate copying inside the response hook. Design decision: retain legacy mutation temporarily or introduce an explicit non-mutating response/attempt ledger with a migration period. Do not silently switch existing `completion.usage` consumers to final-attempt values.

### 2. High: “recursive” accumulation depends on SDK typing and loses current fields

[usage.py:45–69](https://github.com/567-labs/instructor/blob/24752a62/instructor/v2/core/usage.py#L45) recurses through Pydantic models, **not dictionaries or lists**. A numeric extra is added without knowing its units. A dictionary extra replaces the previous value; absent metadata may be carried forward. Boolean values are correctly excluded from arithmetic.

OpenRouter-shaped contract reproduction: costs 0.25 and 0.75 produce `cost=1.0`, but `cost_details.upstream_inference_cost=0.75`, not 1.0. Perplexity's dictionary-valued `usage.cost` has the same overwrite path. These are money fields, not tokens; addition requires a stable currency/account interpretation. See the provider matrix for source definitions.

More immediately, Anthropic 0.93.0 does **not** declare `output_tokens_details`, while current [Messages documentation](https://platform.claude.com/docs/en/api/typescript/messages) does. Decoding it as an SDK extra dictionary means two attempts with 20 output tokens and 12 thinking tokens each yield **40 output / 12 thinking**, not 40 / 24. The contract test uses actual `anthropic.Message` and `Usage` models. At the audited base the field is preserved but stale in the aggregate. **Fixed in this PR:** the Anthropic adapter now adds only documented integer `thinking_tokens` when older SDKs decode both attempts as dictionaries. The corrected result is 40 / 24. Required totals, return types, response mutation, absent/null behavior, booleans, and unknown dictionary metadata retain their existing behavior. Newer nested-model SDK shapes keep the existing accumulator path. A newer SDK that declares a nested model can change this behavior without an Instructor change.

Unknown numeric gauges, timestamps, IDs, or ratios must not be assumed additive. No current-provider ratio is claimed to be miscomputed here: this is the demonstrated generic algorithm's forward-compatibility risk. Nested list data (for example beta Anthropic iterations) must preserve item identities and overlap semantics, not be summed recursively.

Safe next step: provider-specific, documented field contracts plus raw per-attempt preservation. A generic “sum every numeric leaf” patch would repeat the problem with more field shapes.

### 3. High: missing metadata becomes measured zero or an apparently complete subtotal

[retry.py:192](https://github.com/567-labs/instructor/blob/24752a62/instructor/v2/core/retry.py#L192) initializes OpenAI audio/reasoning/cache detail counters to zero; [Anthropic initialization](https://github.com/567-labs/instructor/blob/24752a62/instructor/v2/providers/anthropic/usage.py#L10) does the same for cache fields. The accumulator copies these into absent/null response fields. One ordinary OpenAI response with no detail objects returns `prompt_tokens_details.cached_tokens=0`, even though no cache measurement was reported.

If a detail was present on attempt 1 and absent on attempt 2, its “total” remains the known subtotal, with no field-level completeness indicator. `usage_complete` checks the usage **class**, not individual optional fields. `_usage_total_tokens` uses the direct total or available Anthropic fields; it cannot establish missing-field completeness.

There is an additional failure-only inconsistency: successful unsupported responses omit `_total_usage`, but [InstructorRetryException construction](https://github.com/567-labs/instructor/blob/24752a62/instructor/v2/core/retry.py#L434) attaches the initialized total even when no compatible usage was seen. That can look like zero consumption on a billed failed operation. API errors may have unknown server consumption; SDK-internal retries are not individual Instructor attempts.

Safe candidate fixes: stop fabricating optional details; carry an explicit unavailable/partial signal for exception totals. These alter observable values and require compatibility tests and release notes. This audit does not change their runtime representation.

### 4. High: Responses, beta Messages, and native SDK usage are outside the shared accounting contract

[has_compatible_usage](https://github.com/567-labs/instructor/blob/24752a62/instructor/v2/core/usage.py#L74) admits only OpenAI `CompletionUsage` and Anthropic stable `Usage`, including subclasses. OpenAI `ResponseUsage`, Anthropic `BetaUsage`, Groq, Cerebras, Writer, Fireworks and Mistral usage types are different classes. Google uses `usage_metadata`; Cohere has its own nested usage/meta; Bedrock returns a dictionary. Contract tests reproduce Responses (provider total 15, accumulator still 0), Groq, and beta Anthropic rejection.

Anthropic's [factory chooses beta.messages.create when beta=True](https://github.com/567-labs/instructor/blob/24752a62/instructor/v2/providers/anthropic/client.py#L136), but still initializes stable `Usage`. Thus native Anthropic support itself is endpoint-sensitive. Anthropic Bedrock/Vertex clients passed through `from_anthropic` retain Anthropic-shaped stable/beta semantics; they are different from native Bedrock Converse and Vertex GenerateContent.

The retry budget checks only **after failed parsing**, before scheduling another attempt ([retry.py:371](https://github.com/567-labs/instructor/blob/24752a62/instructor/v2/core/retry.py#L371)). It is not a provider-side cap or a hard ceiling on successful calls. Unsupported metadata triggers `TokenUsageUnavailableError` on a failed parse with a budget; a successful call can return normally without compatible usage. Streaming budgets are rejected up front. Preserve this distinction in documentation.

Safe next step: small endpoint adapters starting with Responses and beta Messages, using their actual SDK response types. Approval needed for the aggregate type and availability representation before adding them.

### 5. Medium-high: streaming, batch, and response-cache results lack a consistent usage outcome

Streaming extraction yields content, not usage. OpenAI [sync/async extraction](https://github.com/567-labs/instructor/blob/24752a62/instructor/v2/providers/openai/handlers.py#L430) drops empty-choice final usage chunks and all Responses events except function argument deltas. Both paths are reproduced with actual `ChatCompletionChunk` objects. Returning a parsed iterator happens before exhaustion, so the retry loop does not finalize an accounting record when a user stops early or cancels. A final event absent due to interruption means **unknown**, not zero. See the lifecycle table.

[BatchProcessor.parse_results](https://github.com/567-labs/instructor/blob/24752a62/instructor/batch/processor.py#L178) discards the successful item's envelope and usage. The contract test proves `BatchSuccess` contains only `custom_id`, parsed `result`, and `success`. Provider-result retrieval before parsing and `BatchJobInfo.raw_data` preserve other routes to raw metadata. Extraction errors retain full raw data; model-validation errors retain only extracted data. Do not mix batch request counters with tokens or add batch summary usage to the same per-item usage.

The local cache [returns before the retry runtime](https://github.com/567-labs/instructor/blob/24752a62/instructor/v2/core/patch.py#L277). [Cache storage](https://github.com/567-labs/instructor/blob/24752a62/instructor/cache/__init__.py#L465) persists parsed JSON and raw response JSON, not a request-level cache-hit marker or `_total_usage`. On a hit it may recreate the raw completion as `SimpleNamespace`, preserving historical usage but not the SDK type. This is a completed-response cache hit with no new provider call, unlike provider prompt caching. Counting restored usage as new expenditure double-counts. Cache key/security work belongs to #2614; this finding is only about result provenance.

### 6. Medium: the CLI is an old estimate surface, not request accounting or an invoice

[cli/usage.py:26](https://github.com/567-labs/instructor/blob/24752a62/instructor/cli/usage.py#L26) queries `/v1/usage?date=...`, not the documented organization Usage/Costs APIs. It does not check HTTP status; errors without a `data` array can render an empty summary. The static price table and [prefix fallback](https://github.com/567-labs/instructor/blob/24752a62/instructor/cli/usage.py#L106) make a `gpt-4o-mini` snapshot match `gpt-4o` prices. Cache, tool, modality, batch and service-tier pricing distinctions are not represented. Internal `total_tokens` counts generated tokens only, but the table does not display it, so this is not currently a displayed total-token error.

The current [organization usage reference](https://platform.openai.com/docs/api-reference/usage) is a separate reporting API. This audit did not query either authenticated endpoint and does not assert the legacy endpoint always fails. Safe correction: label the CLI's estimate limitations. Replacing authentication, endpoint schemas, or prices is separate work; do not mechanically update a few prices and imply financial accuracy.

### 7. Medium: hook snapshots are copied, not immutable, and success shapes vary

A deep copy isolates the usage hook from the accumulator and subsequent attempts ([retry.py:77](https://github.com/567-labs/instructor/blob/24752a62/instructor/v2/core/retry.py#L77)). It is still a mutable SDK object. [Hooks.emit](https://github.com/567-labs/instructor/blob/24752a62/instructor/v2/core/hooks.py#L151) passes the same event arguments to all handlers, so an earlier handler can change what a later handler sees. The docs previously said “immutable”; this PR corrects that wording.

[Finalization](https://github.com/567-labs/instructor/blob/24752a62/instructor/v2/core/retry.py#L121) attaches totals to Pydantic models and `ListResponse`; primitive adapters return their content first, and lazy parallel generators do not gain model attributes. xAI's native factory bypasses this shared retry loop, calls `sample()`/`parse()` directly, and finalizes without a cumulative usage argument ([client.py:260](https://github.com/567-labs/instructor/blob/24752a62/instructor/v2/providers/xai/client.py#L260), sync at 422). Its parallel path returns parsed models from a generator without the enclosing raw response. Do not advertise uniform hooks/budgets/usage for that path.

These abbreviations do not declare universal equivalence. All token fields are counts; durations, monetary amounts and tool requests are separately named. “Absent” means not established by the cited API/type, not a measured zero. All sources below were accessed on the audit date.

## Lifecycle and observability

| Path | What actually happens | User-visible result / limits |
| --- | --- | --- |
| Sync and async structured calls | `patch_v2` prepares provider request then shared retry runtime, except native xAI. Usage processing happens before validation. | Failed validation attempts with supported usage contribute to cumulative totals. Sync/async logic is equivalent by source inspection and existing retry tests. |
| `response_model=None` | Retry functions return the provider call directly before initialization/usage hooks. | Raw provider usage is not accumulated or mutated by this accounting path. User owns stream consumption. |
| Validation retries | Each received full response counted once; request changes can include larger reask history. | Counts reflect the actual returned attempts, not the original prompt multiplied by retry count. `failed_attempts[*].completion.usage` is cumulative at that attempt for A paths. Summing them double-counts. |
| API/SDK transport retries | Failed SDK call raises before Instructor sees a response. Underlying SDK retries/fallbacks can occur inside one Instructor invocation. | No reconstruction of unreported provider consumption. Exception zero/subtotals are not invoice evidence. Network failure does not establish zero cost. |
| Budget | Positive integer validated; streaming and unstructured use rejected. Checked after failed validation only. | Prevents another retry once known token count reaches threshold; successful attempt may exceed it. Missing supported usage on failed parsing raises availability error. No monetary budget. |
| OpenAI Chat streaming | SDK documents `stream_options.include_usage`; final usage chunk has empty choices, other usage can be null. Interrupted stream can lack final chunk. | JSON extractor skips it. Stream object given to response hook is not per-event data. No final total attached to partial models by this runtime. SDK evidence: `openai/types/chat/chat_completion_stream_options_param.py`. |
| Responses streaming | Function argument deltas consumed; completed/incomplete response envelopes are not handled by extractor. | No usage aggregation. A content delta is not a token-usage delta. Do not sum repeated response snapshots. |
| Anthropic streaming | `message_start` carries initial usage; `message_delta.usage` counts are **cumulative**. [Streaming docs](https://platform.claude.com/docs/en/build-with-claude/streaming). [Extractor](https://github.com/567-labs/instructor/blob/24752a62/instructor/v2/providers/anthropic/handlers.py#L225) yields content-block deltas only. | A future adapter must replace/update cumulative fields, not add each message delta; `message_stop` has no independent token increment. Need partial-state outcome on errors/cancellation. |
| GenAI/Gemini/Vertex streaming | [GenAI extractor](https://github.com/567-labs/instructor/blob/24752a62/instructor/v2/providers/genai/handlers.py#L180), [Gemini](https://github.com/567-labs/instructor/blob/24752a62/instructor/v2/providers/gemini/handlers.py#L161), [Vertex](https://github.com/567-labs/instructor/blob/24752a62/instructor/v2/providers/vertexai/handlers.py#L262) consume text/function-call content, ignoring usage metadata. | No Instructor accounting of per-response metadata. This audit does not establish cumulative/delta guarantees for every Google API/version. Preserve terminal metadata; require documented/recorded event fixtures before normalization. |
| Cohere / Mistral streaming | [Cohere](https://github.com/567-labs/instructor/blob/24752a62/instructor/v2/providers/cohere/handlers.py#L138) and [Mistral](https://github.com/567-labs/instructor/blob/24752a62/instructor/v2/providers/mistral/handlers.py#L96) extract content/tool data. Cohere v2 documents usage on message-end; v1 uses stream-end response. [Cohere streaming](https://docs.cohere.com/v2/reference/chat-stream). Mistral event envelope has native usage, but extraction does not aggregate it. | Native final-event inclusion and canceled-stream billing not measured. No guarantee that consuming parsed content exposes final usage. |
| xAI streaming | Native SDK `chat.py:_ResponseProtoDecorator.process_chunk` uses `usage.CopyFrom`. Instructor native factory selects content/argument deltas from `(response, chunk)` pairs. | Usage is a snapshot at SDK level; summing snapshots would double-count. Instructor does not expose those snapshots through parsed stream values. |
| Hosted-compatible streaming | OpenAI content extractor reused. OpenRouter docs explicitly report usage in last SSE message; other services must be checked independently. | Decoder shape and final-event availability matter. Do not assume OpenAI's `include_usage` knob is supported/required by every service. |
| Early close, incomplete output, cancellation | Lazy parsers execute after retry loop returns; there is no `finally` usage settlement in the shared parser path. Nonstream `IncompleteOutputException` propagates separately with last completion. | Known supported usage may already be accumulated before nonstream truncation exception; incomplete/canceled streams may never yield authoritative final usage. No attempt ledger or completeness status. |
| Batch | Only OpenAI and Anthropic supported by batch provider factory. Results parsed independently, bypassing retry usage accounting. OpenAI currently documents batch-level usage on newer batches; Anthropic successful result has Message usage. [OpenAI batch](https://platform.openai.com/docs/api-reference/batch/object?api-mode=responses), [Anthropic results](https://platform.claude.com/docs/en/api/cli/messages/batches/results). | Preserve downloaded result envelopes separately if accounting is required. Never sum summary and item totals together. Counts for succeeded/errored/cancelled/expired jobs are requests, not tokens. |
| Local response cache | Reads/writes through `AutoCache` or other BaseCache before shared runtime; parsed model revalidated on load. | Historical raw usage restored; `_total_usage` not restored; no standard cache-hit provenance or usage event. Contract suite includes a real AutoCache round-trip, no transport. |
| Provider prompt cache | Provider still processes a new request and returns usage with cache details. | Token units, cache-read discounts and cache-write TTL categories remain provider-specific. Entirely separate from local response-cache hits. |
| Hooks / raw access | Completion response hook runs before mutation; usage hook receives one deep copy per event, shared across event handlers. `create_with_completion` and `_raw_response` expose SDK object after mutation. | Immediately deep-copy/serialize the raw hook usage for per-attempt records. Treat `completion:usage` values as cumulative snapshots: replace, do not sum. Primitive results require hooks or a wrapper. |

## Proposed coherent contract (design, not implemented)

Keep **provider metadata first**. Each provider attempt should have a separately preserved SDK/raw usage snapshot plus provider, API family, model, request ID where available, SDK version, stream identity and completion status. No new cost calculator is needed to preserve these facts. Raw SDK metadata is not necessarily raw HTTP bytes: decoding may have already erased unknown fields or protobuf presence.

A future request result can expose an attempt list and an aggregate with explicit availability: `unavailable`, `partial`, or `complete`. Distinguish **absent**, explicit **null**, reported **zero**, and **known subtotal with unknown attempts**. For protobuf fields without scalar presence, label the SDK limitation instead of inventing wire presence. For local cache hits, record `source=local_response_cache` and no new provider attempt; historical usage belongs to the cached source operation.

Candidate normalized quantities and constraints:

| Quantity | Meaning / allowed aggregation |
| --- | --- |
| `input_tokens` | Inclusive processed input only where the provider relationship is established. OpenAI prompt includes cached tokens; Anthropic normalization adds uncached + cache-read + cache-create. Sum across distinct completed attempts with the same definition. |
| `output_tokens` | Inclusive generated/billed output only with a documented definition. OpenAI output includes reasoning/rejected prediction work; Google candidates and thoughts need separate treatment. Keep provider output as raw when equivalence is unresolved. |
| `total_tokens` | Prefer authoritative provider total; derive only from proved additive components. Never include both provider total and its components in a sum. A partial aggregate must not masquerade as a complete total. |
| `cache_read_tokens`, `cache_write_tokens` | Classifications of inclusive input, not additional tokens after inclusive input is computed. Preserve 5-minute/1-hour write categories; their sum is write total, not another chargeable input total. |
| `reasoning_tokens`, `prediction_accepted_tokens`, `prediction_rejected_tokens` | Provider-defined detail categories, normally subsets of inclusive output after normalization. Preserve original names and exact documented relationships. Google thoughts are additional to candidates; xAI native completion must not be assumed OpenAI-inclusive. |
| Modality details | Keep scope (`input`, `cached_input`, `output`, `tool_input`), modality, and token count. Scope lists overlap; do not sum cache+input or thinking+inclusive output. Never turn image count/seconds into tokens without a model-specific rule. |
| Billable quantities | Separate ledger: token counts, seconds, searches, classifications, tool requests, storage, monetary amount + currency/credits. Cohere billed units are distinct from raw tokens. Token counts do not determine cost without pricing context. |
| Unknown metadata | Preserve per attempt unchanged. Do not automatically add unknown numeric fields, booleans, arrays, IDs, percentages, or timestamps. Add normalization rules only with provider-specific evidence. |
| Stream observations | Record whether an event is a delta, cumulative snapshot or final usage. Add deltas once; replace snapshots; deduplicate final usage by request/stream identity. Missing final usage stays partial/unavailable. |

This contract should not require every provider to manufacture every category. Preserve native types for `create_with_completion`, and introduce any normalized view alongside them. Decide public names, mutability, ownership/lifetime, privacy of retained response metadata, and how primitive/parallel/stream/batch results expose the view before implementing a broad API.

## Prioritized implementation plan

1. **Included compact runtime fix: Anthropic thinking details on older SDKs.** Add the documented integer counter across dictionary-shaped details, preserve SDK object types and all existing cumulative totals, and leave unknown metadata/booleans/null behavior unchanged. Regression tests cover typed/dictionary shapes and zero/null/boolean cases. **First follow-up runtime PR:** add opt-in field-presence/availability metadata alongside the existing accumulators, with no changes to existing values. Test absent/null/zero and partially reported details on sync/async success and exhaustion. Removing fabricated zero defaults must be a later explicitly versioned or opt-in migration, not a silent patch.
2. **Second compact PR: availability on retry exceptions.** Add an availability indicator so unsupported/all-missing usage is distinguishable from actual zero on failure. Preserve existing `total_usage` values; changing them to `None` requires an opt-in or deprecation plan. Include native Responses, beta Anthropic and transport-error cases with no paid calls.
3. **Third endpoint PRs: OpenAI Responses, then Anthropic beta.** Use their exact SDK models; only documented fields become additive. Settle aggregate type and primitive/parallel exposure first. Keep SDK-version-bound contracts for beta iterations and newer dictionary extras. Do not imply provider billing parity from local tests.
4. **Provider-owned adapters and stream completion protocol.** Start Google and Cohere (different semantic structures), then Bedrock/Mistral and native compatible SDKs. Add snapshots/deltas/final-event contracts before streaming accounting; represent cancellation without claiming a final bill. Integrate with the existing provider registry rather than adding a parallel registry. Coordinate with the v3/backend task.
5. **Batch/cache provenance and CLI modernization separately.** Preserve per-item batch envelopes; identify historical usage on cache hits without touching cache identity/security behavior. Rework CLI against documented Usage/Costs endpoints only after agreeing account authorization and estimate labeling. Add no generic price inference to retry helpers.

The Anthropic thinking fix is included. A separate typed-dictionary fix for OpenRouter/Perplexity costs may be possible, but must preserve null/presence, units and SDK forward compatibility. It should not precede the absence/availability contract by silently summing arbitrary dictionaries.
