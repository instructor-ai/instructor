# Instructor modularization review after 1.17.0

## Decision and scope

Keep the v2 runtime and improve a few ownership boundaries. A rewrite, blanket file splitting, or a new generic provider framework is not justified. The best first implementation is a small extraction of token-budget policy from retry execution. GenAI configuration ownership and request-local streaming state are more substantial follow-ups.

Reviewed against fetched `origin/main` and local HEAD at **`f539bf2bf43ef4d1cb4e2a405751d6a8815ce05f`**. `pyproject.toml` says 1.17.0. The [v1.17.0 release](https://github.com/567-labs/instructor/releases/tag/v1.17.0) targets that commit and reports publication at 2026-09-09 02:25:36 UTC. Source links below are pinned to this revision; PR status is a review-time snapshot from September 9 UTC.

This is a source-backed design review, not an exhaustive security audit, coverage audit, duplicate-code inventory, or live-provider certification. Read the public exports and compatibility shims, client/router, registry/decorators/protocols, request preparation, response/schema paths, retry/usage/cache, partial and iterable streaming, multimodal/remote boundaries, and representative OpenAI, GenAI, Gemini, Anthropic, and Bedrock paths. Other provider implementations were sampled through capabilities, factories, and callers, not exhaustively certified. No runtime code changed.

## Actual execution and compatibility boundaries

The [root export map](https://github.com/567-labs/instructor/blob/f539bf2bf43ef4d1cb4e2a405751d6a8815ce05f/instructor/__init__.py#L111-L166) resolves public symbols to v2; old core paths are compatibility exports. The regular call chain is:

`from_provider → provider builder/factory → Instructor.create → patch_v2 wrapper → request handler / media / templating / cache lookup → retry_sync_v2 or retry_async_v2 → SDK → registered parser → result finalization → cache store`.

Concrete callers: [client create](https://github.com/567-labs/instructor/blob/f539bf2bf43ef4d1cb4e2a405751d6a8815ce05f/instructor/v2/core/client.py#L538-L573), [async create](https://github.com/567-labs/instructor/blob/f539bf2bf43ef4d1cb4e2a405751d6a8815ce05f/instructor/v2/core/client.py#L793-L845), and [wrapper orchestration](https://github.com/567-labs/instructor/blob/f539bf2bf43ef4d1cb4e2a405751d6a8815ce05f/instructor/v2/core/patch.py#L186-L433). Retry calls `handlers.response_parser` directly. It does **not** call the compatibility `process_response` dispatcher, despite the simplified flow in `docs/architecture.md`. [Direct request/reask helpers](https://github.com/567-labs/instructor/blob/f539bf2bf43ef4d1cb4e2a405751d6a8815ce05f/instructor/v2/core/response.py#L400-L576) remain supported surfaces with their own behavior.

Raw line counts identify reading surfaces only: router 1,619; core client 1,025; OpenAI handlers 1,264; Anthropic handlers 942; core multimodal 890; retry 750; function_calls 622. Overloads, documentation, compatibility methods, and provider modes account for real size. None is independently a reason to split a file.

## Ranked opportunities

All five findings are **P2 maintainability opportunities**, not newly validated production incidents. Ranking considers benefit, safe implementation size, and overlap with existing work.

### 1. Give token-budget policy an owner outside retry execution

**Issue / evidence.** [retry.py:77–119](https://github.com/567-labs/instructor/blob/f539bf2bf43ef4d1cb4e2a405751d6a8815ce05f/instructor/v2/core/retry.py#L77-L119) combines usage snapshots, token counting, and argument validation; [148–189](https://github.com/567-labs/instructor/blob/f539bf2bf43ef4d1cb4e2a405751d6a8815ce05f/instructor/v2/core/retry.py#L148-L189) constructs budget errors. Patch imports `_validate_token_budget` from the execution module and invokes it before preparation. Both retry loops also validate and consult budget errors after parse failure. Usage accumulation already has a distinct owner, `core/usage.py`.

**Why it matters.** A caller that needs preflight policy depends on the retry engine and its DSL/registry imports. Changes to usage accounting, budget semantics, and Tenacity execution meet in the same module even though they have different reasons to change. The practical gain is independent policy tests and a review surface that excludes retry control flow—not fewer lines or a promised speedup.

**Smallest fix / ownership.** Add `core/budget.py` for `_validate_token_budget` and `_budget_error`; move `_usage_snapshot` and `_usage_total_tokens` to the existing `core/usage.py`. Direction: `patch → budget`; `retry → budget + usage`; `budget → usage + errors + messages`. Neither budget nor usage should import patch/retry. Retain imported aliases at old retry names for current direct tests and downstream users. Preserve signatures initially; no policy object, retry superclass, or universal request context.

**Possible non-AI explanation / risk.** These helpers grew next to their first caller, reasonably. Extraction alone is modest value. Do not move `_finalize_parsed_response`, retry setup, SDK usage initialization, hook timing, or exception catches in the same PR. Error payload identity, usage snapshots, and monkeypatch locations can change accidentally even when function bodies do not.

**Acceptance check.** Keep integer retry counts and custom Tenacity policies unchanged. Invalid/streaming/raw budget configurations fail before preparation/provider I/O; exact exhaustion prevents a reask after failed validation; missing compatible usage fails closed on that path; valid output that crosses the budget still returns. Preserve failure history, usage snapshots, and sync/async hooks. Existing [budget contracts](https://github.com/567-labs/instructor/blob/f539bf2bf43ef4d1cb4e2a405751d6a8815ce05f/tests/v2/test_retry_budget.py#L77-L355) explicitly cover these distinctions. **Confidence: High. Release-safe candidate after these checks.**

### 2. Move GenAI request configuration out of legacy Gemini utilities

**Issue / evidence.** [gemini/utils.py:229–326](https://github.com/567-labs/instructor/blob/f539bf2bf43ef4d1cb4e2a405751d6a8815ce05f/instructor/v2/providers/gemini/utils.py#L229-L326) owns `google.genai` safety enums, sampling translation, thinking settings, labels, and cached-content exclusions. Active [GenAI tool and JSON handlers](https://github.com/567-labs/instructor/blob/f539bf2bf43ef4d1cb4e2a405751d6a8815ce05f/instructor/v2/providers/genai/handlers.py#L359-L499) call it. The same legacy utility module also contains schema transformation, message conversion, and Gemini/GenAI/VertexAI request helpers. `instructor.utils.__getattr__` exports some of these paths publicly.

**Why it matters.** A current GenAI SDK change requires navigating a sibling provider's mixed utility module. Importing that sibling executes its package initializer, which imports Gemini handlers. Shared Google schema conventions are reasonable; GenAI SDK config policy is a different owner. Moving only the latter makes protocol changes easier to locate and review.

**Smallest fix / ownership.** In a separate PR, move only `update_genai_kwargs` into `providers/genai/request.py`, keeping its function-local SDK imports and existing behavior. Active GenAI handlers call that owner. Preserve old Gemini/public utility access through lazy compatibility forwarding. Direction: GenAI handler → GenAI request policy; legacy compatibility entry → GenAI request policy. Leave shared schema transforms in place until their independent callers justify a shared Google module.

**Possible non-AI explanation / risk.** The utility module explicitly serves several Google APIs and predates the newer provider layout. Sharing transformations is intentional. An eager re-export is unsafe to assume: both [Gemini](https://github.com/567-labs/instructor/blob/f539bf2bf43ef4d1cb4e2a405751d6a8815ce05f/instructor/v2/providers/gemini/__init__.py#L1-L17) and [GenAI](https://github.com/567-labs/instructor/blob/f539bf2bf43ef4d1cb4e2a405751d6a8815ce05f/instructor/v2/providers/genai/__init__.py#L1-L10) initialize handlers on import. A move can introduce partially initialized-module cycles. Do not rewrite package initialization as an incidental cleanup.

**Acceptance check.** Run GenAI config reuse, config merging, safety settings, and cached-content tests; verify old helper imports and cold import in both provider orders, with each optional Google SDK absent separately. Keep caller-owned `generation_config` reusable in TOOLS and JSON modes. Preserve top-level thinking precedence, base-config precedence, and removal of `system_instruction`/`tools`/`tool_config` for cached resources. Do not “fix” safety defaults, mutate-copy semantics, or merge precedence during the move. **Confidence: High. Release-safe candidate with import-order checks; coordinate with #2608/#2601.**

### 3. Keep per-request streaming state out of shared handler instances

**Issue / evidence.** The [registration decorator](https://github.com/567-labs/instructor/blob/f539bf2bf43ef4d1cb4e2a405751d6a8815ce05f/instructor/v2/core/decorators.py#L39-L67) creates one handler and deliberately shares it across compatible providers. [OpenAIHandlerBase](https://github.com/567-labs/instructor/blob/f539bf2bf43ef4d1cb4e2a405751d6a8815ce05f/instructor/v2/providers/openai/handlers.py#L376-L429) stores streaming flags in a `WeakKeyDictionary` keyed by response model class; preparation marks, parsing consumes. Both [retry](https://github.com/567-labs/instructor/blob/f539bf2bf43ef4d1cb4e2a405751d6a8815ce05f/instructor/v2/core/retry.py#L338-L356) and the [compatibility response path](https://github.com/567-labs/instructor/blob/f539bf2bf43ef4d1cb4e2a405751d6a8815ce05f/instructor/v2/core/response.py#L202-L224) already supply a request's `stream` flag. Direct handler tests also rely on the stored flag, so removing it is not automatically compatible.

**Why it matters.** Request preparation and later parsing communicate through shared mutable state instead of an explicit per-call input. Reused model classes and interleaved calls make that state difficult to reason about. Class memoization proposals increase the importance of this boundary. This is a source-derived interleaving risk, not a reproduced concurrent failure in this review.

**Smallest fix / ownership.** First characterize direct prepare→parse compatibility, then make the regular wrapper/parser path rely on explicit stream input. Handler instances should own mode behavior, not request flags. If legacy flag inference must remain, isolate it as an explicitly supported compatibility path rather than putting request data on every shared handler. Do not introduce a request registry or thread-local workaround.

**Related boundary.** [Partial.extract_json](https://github.com/567-labs/instructor/blob/f539bf2bf43ef4d1cb4e2a405751d6a8815ce05f/instructor/v2/dsl/partial.py#L516-L589) still recognizes OpenAI Responses events when passed a Mode; ordinary handlers already supply extractors. Keep wire-event classification provider-owned in later work, preserving the Mode-based compatibility entry and reasoning callbacks. Do not collapse sync and async iteration or replace existing returns with a universal event/result envelope.

**Possible non-AI explanation / risk.** The state supports older handler callers that prepare with `stream=True` and omit it when parsing. Existing sync partial handling can materialize a list while async handling yields a generator. Changing laziness changes exception timing, hooks, memory, and cancellation behavior. A generator error after values escape cannot safely become an automatic replay without a duplicate-output policy.

**Acceptance check.** Interleave two real handler calls using the same `Partial`/`Iterable` class, including different compatible providers, stream/nonstream, failed preparation, parsing failure, and retry. Consume sync/async streams fully; assert exact emitted values and callback order, including awaited async reasoning callbacks. Keep current direct-handler behavior until maintainers choose its compatibility contract. **Confidence: High on shared state; Medium on replacement scope. Requires maintainer decision before behavior changes.**

### 4. Separate cache storage from runtime response serialization

**Issue / evidence.** [cache/__init__.py](https://github.com/567-labs/instructor/blob/f539bf2bf43ef4d1cb4e2a405751d6a8815ce05f/instructor/cache/__init__.py#L45-L145) defines storage backends, while [276–394](https://github.com/567-labs/instructor/blob/f539bf2bf43ef4d1cb4e2a405751d6a8815ce05f/instructor/cache/__init__.py#L276-L394) inspects client/request identity and [396–494](https://github.com/567-labs/instructor/blob/f539bf2bf43ef4d1cb4e2a405751d6a8815ce05f/instructor/cache/__init__.py#L396-L494) validates models and reconstructs raw responses. The storage package imports v2 async-validator policy. Patch is the active load/store caller; it computes identity after templating and before retry isolation.

**Why it matters.** A storage abstraction and the public runtime's response semantics change for different reasons. A backend should store bytes/values and honor TTL; it should not decide Pydantic validation or how SDK completions are reconstructed. Separating those concerns makes cache-hit behavior testable independently of eviction/backend behavior.

**Smallest fix / ownership.** After #2614, consider moving response load/store implementation to `v2/core/cache_response.py`. Direction: patch → response codec → cache backend interface + validation policy. Keep `BaseCache`, backend implementations, and public entry points in `instructor.cache`; use lazy compatibility forwarding to avoid a new eager cycle. Leave identity helpers and their bytes unchanged in the first PR. An additional key-policy module is justified only by a concrete caller/change, not symmetry.

**Possible non-AI explanation / risk.** One module made cache convenient to adopt, and public helpers constrain separation. Cache hits currently restore some raw responses as `SimpleNamespace` or plain data, not original SDK classes; the envelope stores `model` and `raw`, not accumulated usage. Preserve these facts in a move. Adding versioned envelopes, async storage, full SDK reconstruction, or changing cache eligibility requires an independent compatibility decision.

**Acceptance check.** Same key bytes, namespace isolation, TTL, cache miss/bypass behavior, current context/strictness, legacy bare model JSON, raw-response shape, and backend exceptions. Run cache tests plus #2614's contracts after it lands; assert behavior through real SDK/local HTTP calls rather than new registry mocks. **Confidence: High on mixed responsibility; Medium on payoff relative to compatibility cost. Defer until active cache work settles.**

### 5. Route provider construction without owning every SDK's options

**Issue / evidence.** `from_provider` dispatches through `_PROVIDER_BUILDERS`, but the router also owns SDK construction and request/client option separation. [Google construction](https://github.com/567-labs/instructor/blob/f539bf2bf43ef4d1cb4e2a405751d6a8815ce05f/instructor/v2/auto_client.py#L608-L681) extracts credentials, HTTP settings, location, and project; [Bedrock construction](https://github.com/567-labs/instructor/blob/f539bf2bf43ef4d1cb4e2a405751d6a8815ce05f/instructor/v2/auto_client.py#L976-L1060) owns AWS environment precedence, region defaults, boto3 construction, and model-dependent default mode. Provider client modules then wrap native SDK calls.

**Why it matters.** A provider SDK constructor change reaches the shared router even when routing syntax is unchanged. Provider-owned builders would make ownership clearer and reduce the number of shared modules a provider maintainer must understand.

**Smallest fix / ownership.** Discuss selective reconstruction with #2355's owner. Move one builder into its provider package behind lazy dispatch, preserving its parameters initially. Direction: router → provider builder → native SDK + provider factory → core patch. Keep `ProviderSpec` declarative; do not replace SDK semantics with a growing bag of constructor flags, arbitrary method-path strings, or generic exception rewrites.

**Possible non-AI explanation / risk.** A central router is easy to discover and preserves one place for initialization diagnostics. SDK option differences are real: Google vertex settings are not AWS credentials, and model-dependent defaults are not a universal capability rule. A new layer that merely forwards the same large dictionary without moving ownership buys little. Existing stack overlap makes this the lowest-priority independent implementation.

**Acceptance check.** Public `from_provider` overloads, aliases, missing-SDK/error precedence, environment-vs-explicit credentials, endpoint/default model selection, supplied client ownership, and native sync/async method selection. Use existing provider construction tests and a real SDK/local endpoint contract for the selected provider; retain cold-import tests. **Confidence: High on boundary; Medium on net benefit until #2355 is reconciled. Maintainer coordination required; no competing factory rewrite.**

## Boundaries to preserve, and changes not recommended

- **Registry and imports:** `registry → dynamic provider import → decorator → registry` is an intentional registration cycle, not proof of a broken import. Lazy-loader locking already exists. Preserve failed-load retryability, single shared handler identities, custom registration, and optional SDK laziness. Static import edges alone cannot prove runtime initialization safety. Do not introduce a plugin discovery framework or globally eager provider import.
- **Schema and compatibility:** `response_model.py` normalizes user types; provider schema modules translate them; `function_calls.py` retains substantial compatibility methods. Keep public class identity, aliases, warnings, TypedDict requiredness, context, and strictness. Delegate memoization correctness to the existing schema PRs. Do not split `ResponseSchema` into mixins just to reduce its file length.
- **Request/response orchestration:** patch legitimately sequences preparation, media conversion, templating, cache, and retry. Avoid a pipeline of pass-through classes or a mega `RequestContext`. Separate response-finalization paths have observable scalar/list/raw/usage behavior; their apparent overlap belongs in the separate duplicate-code review and should not be unified here without contract evidence.
- **Sync/async:** retain separate execution shells. Share small policy functions only. Synchronous cache access and media acquisition inside async preparation are real design considerations, but moving files does not make them nonblocking. An async storage/media API or thread-offload policy requires measured need and explicit resource/cancellation semantics.
- **Multimodal:** bounded fetching already has `core/remote.py`; provider encoders already exist. Preserve source validation, pinned destinations, size/redirect limits, and the distinction between Instructor downloading a URL and forwarding it for provider fetching. No generic media-loader rewrite or splitting every media class is justified by this review.
- **Provider differences:** preserve wire-specific reask roles, function IDs, refusals, finish reasons, tool/schema settings, and stream events. OpenAI-compatible shared handlers are useful where contracts match; provider-specific modules are useful where they differ. Batch/CLI remain separate workflows, not additions to retry orchestration.

## Staged PR plan and actionable first slice

| Stage | Scope | Gate |
| --- | --- | --- |
| This PR | Review document only | Verify source references and baseline contracts |
| A | Budget policy extraction: one new `core/budget.py`; edit `retry.py`, `usage.py`, `patch.py`; focused tests only | Preserve bodies, error types/payloads, aliases and call order; no retry algorithm changes |
| B | One GenAI config function moves with compatibility forwarding | Two SDK import orders, optional dependency absence, config precedence/reuse; reconcile provider fixes first |
| C | Characterize and decide request-local streaming contract, then a separate implementation PR | Maintainer decision on legacy inference and return/lifecycle semantics; coordinate schema memoization |
| D | Cache response codec extraction | Land/reconcile #2614 first; byte/shape compatibility; defer envelope/API changes |
| E | Select one provider builder from #2355 | Agree stack ownership and current-main parity before implementation |

**Stage A implementation checklist:**

1. Move exactly `_validate_token_budget` and `_budget_error` to budget; move `_usage_snapshot` and `_usage_total_tokens` to usage. Keep current keyword-only arguments and exception construction unchanged. Retain old retry symbols as import aliases.
2. Patch imports preflight validation from budget. Retry imports policy and usage helpers, leaving all invocation sites and order intact. No changes to the supported providers, token arithmetic, serialization, or what counts as a retryable error.
3. Run `tests/v2/test_retry_budget.py`, `tests/v2/test_retry_runtime.py`, `tests/test_update_total_usage.py`, and cold-import tests. Existing budget tests include internal monkeypatches; retain their expectations, but add any missing boundary case using direct policy inputs or a real SDK/local HTTP response. Do not add mocks to make an extraction pass.
4. Verify exact-boundary failed validation, successful output over budget, unavailable usage, sync/async preflight, and snapshots across attempts. Check imports do not create a budget↔retry edge. Preserve aliases and installed-package typing.
5. Run repository lint/type checks and the normal offline CI selection for the implementation PR. Changelog required if any behavior changes; a behavior-preserving move must not silently become a policy fix. Stop and separate a behavioral discrepancy found while extracting.

Stages A/B are candidates for ordinary incremental releases **after** validation, not unconditional release approvals. Streaming lifecycle, cache envelope/API, global provider construction policy, or v3 adoption need separate maintainer decisions.
